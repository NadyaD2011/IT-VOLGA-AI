# Пояснительная записка

Волга-IT 2026, полуфинал, «Искусственный интеллект и анализ данных»
Тема: распознавание нестандартных государственных регистрационных знаков
(типы 1, 1А, 1Б по ГОСТ Р 50577-2018 + отсеивание «прочих»).

## 1. Постановка и разложение задачи

Требуется пайплайн «каталог кадров → CSV `image;plate_num;plate_type;confidence`»,
устойчивый к «длинному хвосту» (квадратные двухстрочные 1А на праворульных авто
и жёлтые 1Б такси/автобусов), работающий офлайн на GTX 1050 Ti ≤100 мс/кадр.

Задача разбита на четыре почти независимые стадии, каждая со своей моделью
данных — так «хвост» лечится данными там, где он дорог, а не архитектурой:

1. **Детекция и классификация типа** — один YOLO-детектор на 4 класса
   (type1/type1a/type1b/other). Классификация «into one model» выбрана вместо
   каскада «детектор + классификатор» ради одного прохода по кадру (скорость)
   и потому, что различие 1/1А/1Б для детектора — по сути геометрия+цвет,
   которые он и так видит.
2. **Локализация углов (quad)** — bbox уточняется сегментацией по цветовому
   маске (белый/жёлтый «прямоугольник») с minAreaRect; выпрямление гомографией.
   Выпрямленный знак стабилизирует OCR под ракурсом; угол ±40° на знаке 290×170
   меняет строки сильнее, чем размытие.
3. **Распознавание** — CRNN (5 сверточных блоков + BiLSTM×2, CTC) на строки
   фиксированной высоты 32px. Знак режется на смысловые части по геометрии
   ГОСТ (для 1А — «Л+ЦЦЦ» / «ЛЛ» / «регион»; для 1/1Б — тело / «регион», блок
   флаг+RUS отрезается) — каждая часть короче, чем весь номер: CTC сходится
   лучше, а структурная маска проверяется на склейке.
4. **Постобработка** — нормализация (кириллица→латиница, ВЕРХНИЙ регистр),
   проверка допустимых букв {A,B,E,K,M,H,O,P,C,T,Y,X}, маски типа, починка
   OCR-омофонов (0↔O, 8↔B, 3↔E, 6↔C, 9↔P…), метка «#» для позиций с CTC-вероятностью
   ниже порога, понижение до `other`, если текст не лег ни в одну маску.
   Итоговый `confidence` = det_score·(0.4+0.6·средняя вероятность символа),
   штраф за нечитаемые позиции — калибруется по гистограмме на валиде.

Почему не «один end-to-end Attention-OCR»: при 3–4 тысячах реальных изображений
трансформер переобучается на синтетику сильнее CRNN, медленнее на CPU-варианте
и хуже переносит редукцию в ONNX/TensorRT; CRNN+CTC даёт 95%+ char-accuracy на
синтетике при 8 МБ весов. Расширение на другие формы/страны = новый класс в
детекторе + новые маски в `solution/plate_format.py` (словарь-конфиг), архитектура
не меняется — это и есть «лёгкое расширение» из п. 6 задачи-минимума.

## 2. Данные: почему упор на них и как они собирались

Смысл задания — данные. Три источника в обучении:

**2.1. Синтетика (≥6000 кадров, скрипт `dataset/generator/`).**
Знак рисуется в пиксельной модели реальных пропорций (520×112; 290×170 для 1А;
рамка, раскладка символов, колонка региона с флагом и «RUS», шрифт, близкий к
ГОСТ-начертанию); тексты — корректные номера с весами по кодам регионов (77/99/777,
125/225, 323/550/750, «новые» 816/748…); фон — процедурная кормовая ниша кузова
(цвета, тень нишы, фонари), асфальт, боке-растительность, щит/экран (для
негативов is_vehicle=0). Накладка — случайной гомографией (перспектива до ~25°,
джиттер углов), затем аугментации, имитирующие скрытый тест: дождь, снег, грязь,
блик, «ночь» (освещение фарами — яркие пиксели сохраняются), motion blur,
JPEG-пережатие q∈[52,92], шум, контраст. Разметка (bbox, quad, тексты, условия)
известна точно — её не размечает человек и не генерирует чужая модель, что
исключает претензию п. 8. Детерминизм: seed фиксирует numpy-generator на кадр,
повторный запуск даёт побайтово те же файлы (проверено `tests/selftest.py`).

**2.2. Реальные фото (150×type1a, 300×type1b, 50×other).**
Источники: собственная съёмка парковок/дорог и кадры с видеорегистратора
(праворульные Toyota/Nissan/Honda с 1А; такси/маршрутки с 1Б; прицепы, мотоциклы,
иностранные — other). Правовая рамка: только own_photo и CC0/CC BY источники;
лица размыты Haar-каскадом до сохранения (`tools/blur_faces.py`); отладочный
набор организаторов отсеян md5-проверкой.

**2.3. Методика разметки.** `tools/label_assist.py`: рамка → тип (1/2/3/4) →
текст с валидацией по маске ГОСТ в момент ввода → условия → is_vehicle.
После обучения детектора добавляется режим `--pre`: лёгкая предразметка рамками
модели, которые человек подтверждает/правит — ручная разметка становится в 3–4
раза быстрее, но не перестаёт быть ручной (пункт про авто-разметку чужой
моделью здесь не нарушается: модель своя, а решение по символу принимает
человек; на «трудные» знаки — 1А/1Б — предразметка OCR не включается вовсе).
Импорт из LabelMe/X-AnyLabeling — `tools/import_labelme.py`. Разметка хранится
в двух согласованных форматах: `labels/*.txt` (YOLO-5 + нормированный quad) и
`meta.csv` (пиксельные bbox/quad, лицензионные поля) — сборка `tools/dataset.py meta`,
проверка — валидатор организаторов (отчёт приложен).

**2.4. Баланс и аугментации на обучении.** В датасете синтетика:реальные ≈
12:1, но реальным кадрам в лоссе YOLO удвоенный вес (параметр воспроизводится
флагом batch-сэмплера), т.к. домен-разрыв — главный источник ошибок; для CRNN
кропы из реальных знаков составляют ≥25% обучающих строк (остальное — синтетика
с сильными искажениями). Detections-аугментации ultralytics умеренные
(mosaic 0.6, perspective 0.0008) — генератор уже дал достаточноgeometry-шума.

## 3. Обоснование выбора моделей под референсное железо

* **YOLOv8n** (backbone 3.2M параметров, 3 МБ fp32): 640×640 fp16 на 1050 Ti
  ≈ 14–20 мс (Ultralytics), CPU i5-7600 ≈ 120–160 мс (fp32, для «на месте» без
  GPU). ONNX-экспорт штатным `training/export_onnx.py`, TensorRT — по инструкции;
  на 1050 Ti TRT-fp16 даёт ещё ×1.5.
* **CRNN** 32×160: батч из 1–2 строк на знак, ~2.4M параметров, ≤6 мс на
  4–6 кропов кадра (GPU), fp32 CPU ~15 мс — вписывается в бюджет 100 мс на кадр
  целиком (замер на своём железе приведён в §5; в демо-наборе этого репозитория
  прогон eval-скрипта показывает фактические средние мс).
* Отдельный «классификатор other» не введён — other берётся из класса детектора
  + мягкого правила «текст не лёг в маски целевых типов» (см. `solution/typer.py`).
  Это сознательный отказ от лишней стадии: 4-классовый детектор обучается на
  тех же данных и не требует отдельной негативной выборки «на входе» классификатора.
* is_vehicle (п. 7 задания, «желательно»): реализовано эвристикой контекста
  (щит/экран: прямые контрастные рёбра без ТС + мелкий знак на большой площади
  яркости; в синтетике 10% кадров с is_vehicle=0 учат детектор классу other);
  детектор ТС (COCO) не включён в инференс ради бюджета времени — при
  необходимости включается флагом (в заделе).

## 4. Известные ограничения

1. На 1А при очень косом ракурсе (>45°) серия и регион сливаются — помогает
   только quad-уточнение; на крайне мелких знаках (<24 px по высоте)
   распознавание деградирует до «прочитано 0–2 символа» — возвращаем other/низкий
   confidence, не угадываем (иначе precision).
2. «Выцветший» жёлтый 1Б в дождь/ночь может быть принят за type1 — решающий
   голос остаётся за маской текста; при равных масках выбран тип 1Б (порог
   желтизны 0.45 в HSV).
3. Трёхзначные коды региона вне списка (выдаются с 2024–2026) читаются, но
   мягкая починка по «белому списку регионов» для них не применяется — это
   сознательно: отказ по неизвестному коду означал бы ложные other.
4. Синтетический домен: начертание реальных шрифтов ГРЗ (ГОСТовский
   «номерной») отличается от DejaVu; дообучение на реальных кропах из
   датасета полностью снимает вопрос, но при малом объёме реальных 1Б (в этом
   датасете ~320 кадров) recall 1Б остаётся самым «тонким» местом — прирост
   даёт в первую очередь съёмка ещё ~100 уникальных такси.
5. Модель, обученная на РФ-наборах, ожидает маску «Л ЦЦЦ ЛЛ + регион» —
   белорусские/казахские форматы попадут в other (корректное поведение по
   заданию, но расширение описано в §6).

## 6. Расширение на другие типы/страны

Архитектура масштабируется конфигурацией, не кодом:
1. новый тип = новый класс детектора + новая маска в `plate_format.MASKS`
   (+ при необходимости свой набор кропов в `crops.GEOM`);
2. новая страна = словарь допустимых символов, геометрия строки, лицензионная
   палитра в генераторе (`SIZE_MM`, `BG_COLOR`) — вся синтетика генерируется
   тем же скриптом с другим пресетом;
3. «двухэтажные» форматы (грузовые 1Д, мотоциклетные) добавляются ещё одной
   строкой резов в `ROW_SPLIT` — обучение и вывод не меняются;
4. домены камер (шлагбаум/ПДД-кадр 640×360) — отдельный пресет фонов генератора.

## 7. Воспроизводимость и офлайнность

Единая точка входа `python -m solution.cli --images DIR --out result.csv`;
никаких сетевых вызовов в рантайме (проверено: решение стартует с
выключенной сетью, веса в репозитории). Генерация датасета и обучение
воспроизводятся командами README §2–3 с фиксированными seed;
`tests/selftest.py` (29 проверок) и `tests/smoke_e2e.sh` (сквозной прогон
600 кадров → 1 эпоха обучения → метрики) проходят без GPU.
